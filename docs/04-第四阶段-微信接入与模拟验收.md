# 第四阶段：微信接入代码与模拟验收

## 阶段结论

已实现可配置的微信身份登录、校内名单一次性绑定、主动申请一次性订阅、服务器提醒发送和结果记录。**当前仅完成模拟微信接口验收**。没有可用的 AppID、AppSecret、HTTPS 服务域名及订阅消息模板，无法验证微信开发者工具编译、真机登录、平台授权、平台实际发送和送达。柜锁与取还检测仍为模拟，留到实体设备阶段。

| 目标 | 模拟验收结果 | 真实联调状态 |
| --- | --- | --- |
| 微信登录与校内身份分离 | `wx.login` 临时 code 只发到服务端；服务端换取 OpenID。未绑定微信账号不能借伞，不能仅凭姓名和学号绑定。 | 待 AppID、AppSecret 和真机。 |
| 一次性身份绑定 | 管理员核对已导入名单后生成128位随机绑定码，有效期1小时、用后失效。学生核对姓名、学号、班级；教师核对姓名、工号、电话。同一个微信身份只能绑定一位师生。 | 待学校确认名单与凭据发放办法。 |
| 微信订阅提醒 | 借伞取走后由用户点击申请。服务端记录站内提醒、订阅同意次数、发送尝试及微信接口结果。无同意记“未授权”，接口失败记“失败”，接口接受也不冒充送达或已读。服务恢复后多个过时节点只外发最新一条。 | 待模板 ID、模板字段及真机授权。 |
| 保持实验边界 | 默认仍为虚构身份演示；微信联调模式使用独立数据库及强管理员口令，关闭时间快进与数据重置，以免触发真实微信消息。 | 真实柜锁和小程序发布均未完成。 |

## 运行方式与配置

无配置时直接运行 `npm start`，仍使用 `data/state.sqlite` 和公开演示身份。只有准备好微信资料后才启用联调模式；任一微信配置缺失会拒绝启动，避免半配置状态。联调模式使用独立的 `data/wechat.sqlite`，第一次启动从名单文件初始化；名单变更不会静默改写已有身份，程序会提示先备份并处理数据库。

| 环境变量 | 用途 |
| --- | --- |
| `WECHAT_APP_ID`、`WECHAT_APP_SECRET` | 小程序 AppID 和服务端 AppSecret。AppSecret 不写入代码仓库、小程序包或浏览器页面。 |
| `WECHAT_TEMPLATE_ID` | 在微信公众平台配置的一次性订阅消息模板 ID。 |
| `WECHAT_TEMPLATE_DATA_JSON` | 与所选模板实际字段完全对应的 JSON，例如从私有配置文件读取；可用 `{{umbrellaId}}`、`{{stage}}`、`{{dueAt}}`、`{{message}}` 占位符。参考 `config/wechat-template.example.json`，字段名需按实际模板调整。 |
| `UMBRELLA_ROSTER_FILE` | 校方核验名单的绝对文件路径。格式参考 `config/roster.example.json`；示例只有虚构身份。真实名单建议放在被 Git 忽略的 `data/` 或独立安全目录。 |
| `UMBRELLA_ADMIN_PIN` | 至少12位的管理员口令，替代公开的演示口令。 |
| `UMBRELLA_PUBLIC_URL` | 手机可访问的 HTTPS 域名根地址，例如 `https://umbrella.example.org/`；打印标识默认使用此地址。 |
| `WECHAT_MINIPROGRAM_STATE` | 消息卡片跳转版本：`developer`、`trial` 或 `formal`；未设置时为 `formal`。 |
| `UMBRELLA_PORT` | 可选；联调时可用8767端口，与本地演示隔离。 |

微信开发者工具中还需将 `project.config.json` 的 `appid` 改为自己的小程序 AppID，并把根目录 `app.js` 的 `baseUrl` 改为手机可访问的 HTTPS 服务地址。该域名需按微信平台要求配置为小程序合法请求域名；`127.0.0.1` 只能用于电脑本机调试。订阅消息的字段类型和长度须与实际选定模板一致。标识二维码目前仍是网页链接，小程序扫码可以识别编号，但不是正式小程序码。

## 已执行验收

运行 `npm test`：共14项测试，**14通过、0失败**。第四阶段测试使用临时数据库与模拟微信接口，覆盖：演示登录在微信模式被拒、管理员强口令、未绑定账号不能登录、错误校内资料被拒、绑定码一次性使用、OpenID 不回传到客户端、微信登录后借伞、未取走不能订阅、用户不同意不记录授权、接口受理仅记录受理、无授权不发送、发送失败不重复尝试、服务恢复后只外发最新节点、时间快进与重置默认关闭。服务端适配器的 code2Session、access token 和订阅发送请求也使用假 HTTP 返回验证，测试期间未联系微信服务器。小程序 JavaScript 语法及 WXML 结构可在本机检查，但真实微信开发者工具和手机上的运行仍待验证。

获得联调资料后的真机验收顺序：导入校方确认的测试名单与模板配置；管理员为测试学生和教师分别发码；两种身份各完成一次绑定、重新登录和借还；用户主动同意或拒绝订阅，分别检查站内记录与微信接口状态；再核对手机是否收到平台消息。微信接口返回成功只能证明请求被接受，不能单独证明用户已收到或已阅读。

参考微信官方文档：[小程序登录](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/login.html)、[订阅消息](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/subscribe-message.html)、[网络要求](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html)。
