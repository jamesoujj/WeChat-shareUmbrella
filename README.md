# 晴雨之间：格致中学校园爱心伞实验

基于 [LiaPig/WeChat-shareUmbrella](https://github.com/LiaPig/WeChat-shareUmbrella) 的 fork，按课题方案改造为免费、免押金的校园实验：师生自助借还、编号仓位、演示身份绑定、积分、分级提醒、拍照报修和后台维修管理。旧版押金、充值、付款、地图及第三方 HTTP 接口已移除。服务端与网页演示基于此前的本地实验原型整合而来。

页面与可打印标识已加入“上海市格致中学”字样。正式校徽图样仍需使用学校提供或确认的文件；当前伞形图标只是本实验的项目图标，不能当作学校校徽。

## 直接演示

双击 **启动演示.cmd**，浏览器会自动打开。演示期间保留启动窗口，关闭窗口即停止服务。

首次运行需要 Node.js 24 或更新版本，并安装二维码组件。Node.js 24 自带本项目使用的 SQLite 模块，不需要另装数据库服务。安装依赖后，日常演示不依赖外网。

| 身份 | 姓名 | 编号 | 口令 |
| --- | --- | --- | --- |
| 学生一 | 演示同学一 | S2026001 | 123456 |
| 学生二 | 演示同学二 | S2026002 | 123456 |
| 教师 | 演示老师 | T0001 | 123456 |
| 管理员 | 无需填写姓名 | 无需填写编号 | 2026 |

这些都是虚构的测试身份。学生还需填写“高二（1）班”或“高二（2）班”；教师需填写演示电话“00000000000”。姓名、编号、班级或电话及口令须与演示名单一致；未登录访客不能借伞。这里没有接入学校学籍系统，也没有验证微信账号。

## 三分钟演示顺序

1. 使用学生身份认证，选择1号伞。仓位模拟开锁后，点击“模拟检测到取伞”，才开始48小时借期。
2. 点击归还，确认放入1号仓位。页面提交归还信息后，再模拟仓位在位检测与锁闭；成功后积分从100增加到102。
3. 再借一把伞并确认取走，展开下方“实验控制台”，依次点击“推进24小时”“再推进48小时”“再推进48小时”。首次输入管理员口令2026。
4. 查看“我的记录”：出现借出24小时、逾期1天和逾期3天的站内提醒；此时逾期已满3天，累计扣30分。
5. 归还弹窗可以选择错误仓位，系统会拒绝编号不匹配。选回正确仓位后完成归还；逾期归还不增加按时奖励。
6. 借用另一把伞，可先点“上报雨伞损坏”，填写部位并拍照；还伞时也能直接勾选“这把伞已经坏了，需要报修”并上传照片。归还完成后自动转待维修，管理员可查看说明与照片，修好后将它改为“可借用”。
7. 切换教师身份，演示教师也能借用。最后可在控制台重置实验。

## 实验积分规则

第一版规则见 [第一阶段规则与验收基线](docs/01-第一阶段-规则与验收基线.md)，参数在 `server.js` 的 RULES 与 STAGES 中。

- 初始100分，上限120分；按时归还奖励2分；借期48小时，从模拟检测到取走时开始。
- 到期后每满24小时扣10分，最低0分；借出24小时、逾期1天、逾期3天分别记录一次站内提醒。
- 低于60分限制新借用；归还后仍低于60分，则恢复到70分。逾期归还不发放按时奖励。
- 每人同时只能借一把；归还必须匹配雨伞编号和固定仓位编号。
- 时间推进会影响所有演示账号。逾期与遗失分别记录，系统不会把逾期自动判作遗失。设备故障可冻结后续自动扣分，管理员核对后结案。

## 模拟范围

借还、权限判断、积分、记录、编号校验、状态管理、报修照片存取和二维码生成实际运行；借还数据保存在 `data/state.sqlite`，照片保存在 `data/photos`，重启后仍保留，登录需要重新进行。此前演示使用的 `data/state.json` 原样保留作为旧版数据，不自动混入新版规则。照片只允许上报者与管理员查看；重置实验会清除新数据库中的实验记录及实验照片。

正常借还完全由师生自助完成，管理员只处理维修、补货等异常。第二阶段把开锁、取伞、入仓和锁闭拆成独立状态：开锁或勾选确认本身不算借出/归还，必须由设备模拟事件完成。网页与小程序中的“模拟检测到取伞”以及归还时的检测事件仅供实验验证，仍未连接实物柜；真实柜体需用经过认证的设备事件代替。消息存入站内提醒列表，没有接入微信订阅消息、短信或手机后台推送。服务运行时每秒检查提醒；服务关闭期间不推送，重新启动或访问后补算已到期阶段。

二维码进入手机网页演示，不是已发布的微信小程序码。仓库根目录的 `app.js`、`app.json`、`app.wxss`、`pages/` 是微信小程序客户端源码，连接同一个实验服务；需要微信开发者工具导入验证，不代表已经完成小程序发布。

## 伞和仓位二维码

网页伞柜下方可选择编号，分别打开并打印“伞标识”和“仓位标识”。每张标识包含学校名称、编号、归还对应关系和二维码。手机扫描伞二维码会显示该伞状态与对应仓位；扫描仓位二维码会显示仓位信息，已登录且编号匹配时可进入归还操作。小程序内也可点击“扫描伞 / 仓位标识”读取这些网页二维码的编号；这是实验识别流程，并非微信小程序码。

打印前先用“启动手机演示.cmd”运行服务，并在网页的入口二维码处选择手机能访问的电脑局域网地址，再打开标识。使用本机 `127.0.0.1` 地址生成的标识只能在电脑上访问；电脑地址变化后需要重新打印标识。

## 手机访问

先关闭原来的启动窗口，再双击 **启动手机演示.cmd**。电脑和手机接同一网络，在页面二维码下选择电脑对应的局域网地址，用手机浏览器扫码打开。电脑网络有多个地址时，请选择与手机同一网段的地址。

默认启动仅允许本机访问；手机模式监听局域网。程序不会自动修改系统防火墙设置。网络或防火墙不允许访问时，仍可直接在电脑演示。测试账号和口令公开，不要把此实验服务发布到公网或录入真实师生资料。

## 微信小程序源码

1. 先启动本地演示服务。
2. 在微信开发者工具中导入本仓库根目录，使用自己的测试项目 AppID；`project.config.json` 默认使用游客测试标记，不再使用原作者的 AppID。
3. 本地调试时将 `app.js` 的 `baseUrl` 保持为 `http://127.0.0.1:8766`；在开发者工具里开启本地调试的“不校验合法域名”选项。这里的本地地址与设置仅用于开发调试。真机预览需要手机可访问的 HTTPS 服务和微信后台配置的合法域名，不能直接依靠电脑的 `127.0.0.1`。
4. 小程序源码已加入自助借还、模拟取伞确认、拍照报修、本人和管理员查看照片、个人记录、提醒、库存/逾期查看与时间推进。正式微信身份、订阅消息、真机联网、发布和硬件均尚未接入；该客户端还需要在微信开发者工具和手机上实际验证。

## 文件与检查

`server.js` 是实验规则和本地服务，`lib/store.js` 负责 SQLite 存取；`public/` 是浏览器界面；仓库根目录的小程序文件与 `pages/` 是微信客户端；`test.js` 是自动检查。默认浏览器地址为 `http://127.0.0.1:8766/`，与之前独立原型的 8765 端口互不干扰。同一个数据库只由一个服务进程使用。

在本文件所在目录运行 `npm test`，会在临时目录验证开锁失败、两人抢同一把伞、60秒未取伞取消、错误仓位和未锁闭不得归还、积分时间边界和上限、三级提醒、报修照片权限、维修、设备故障、延迟事件补传以及 SQLite 重启保存，不会修改你正在演示的数据。设备模拟接口 `/api/demo/device` 只用于本地演示，不代表真实硬件已接入；正式使用前必须替换为设备认证通道。
